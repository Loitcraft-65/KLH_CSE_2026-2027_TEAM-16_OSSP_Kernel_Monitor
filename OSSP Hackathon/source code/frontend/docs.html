1. Abstract & Executive Summary

In modern computing systems, storage capacities and directory depths continue to expand exponentially, yet everyday search utilities frequently execute file traversal sequentially. Sequential file search underutilizes multi-core microprocessor capabilities, resulting in idle CPU cycles and extended user latency during deep directory crawls.

AeroSearch is an end-to-end, high-concurrency file traversal and full-text pattern matching engine designed for the OSSP Hackathon. The computational foundation of the project is implemented entirely in C using POSIX Threads (pthreads). To eliminate the thread starvation common in static partitioning, AeroSearch develops a dynamic work-stealing task queue coordinated by fine-grained mutual exclusion locks (pthread_mutex_t) and condition variables (pthread_cond_t).

Key Metric Achieved: Benchmarks across an 800-file nested directory demonstrate that AeroSearch scales from 99.87 ms (1 Thread) down to 35.67 ms (4 Threads), achieving an empirical 2.80x speedup and processing over 22,400 files/second before saturating system I/O buses.

2. Problem Statement & Motivation

Standard command-line utilities such as basic find or single-threaded recursive grep algorithms examine the file system sequentially. When scanning directories containing tens of thousands of mixed source code files, logs, and binaries:

  1. I/O Blocking: While a single thread waits for disk blocks to be transferred into memory buffers, the processor remains in an I/O wait state.
  2. Unbalanced Subtrees: Subdirectories in software repositories are fundamentally asymmetrical. For example, a node_modules or logs folder may contain 15,000 files, while a sibling config folder contains only 3. Naive static thread division leads to severe load imbalance.
  3. Lack of Observability: Typical search CLI tools operate as black boxes, providing no live telemetry on active worker threads, per-core throughput, or real-time progress.

The objective of Team 16 was to construct a robust, production-grade parallel search platform combining low-level C concurrency with a real-time web interface.

Tier Descriptions

1. Computational Core (C Engine): A statically linked standalone binary (parallel_search.exe) compiled with gcc -Wall -Wextra -O3 -static. It performs all directory entry querying (opendir, readdir), file chunk reading, and regex/substring comparisons.

2. Orchestration Bridge (FastAPI): Spawns the C engine as an asynchronous child process using asyncio.create_subprocess_exec. Real-time telemetry JSON lines output by C are parsed and broadcast immediately over WebSockets.

3. Cyber-Industrial Frontend: A responsive, zero-build web interface (HTML5, Vanilla CSS, Canvas 2D) rendering worker status cards, dynamic line-number highlights, and Amdahl's Law scaling charts.

4. Concurrency Model & OS Synchronization

4.1 Dynamic Producer-Consumer Task Queue

The queue is defined in c_engine/queue.h as a linked FIFO queue holding two task types: TASK_DIRECTORY and TASK_FILE. 

typedef struct Task {
    char path[MAX_PATH_LEN];
    TaskType type; // TASK_DIRECTORY or TASK_FILE
    int depth;
    struct Task* next;
} Task;

typedef struct {
    Task* head;
    Task* tail;
    int count;
    int active_workers;
    bool shutdown;
    pthread_mutex_t lock;
    pthread_cond_t not_empty;
} TaskQueue;

4.2 Synchronization Primitives & Deadlock Prevention

Worker threads interact through strict synchronization invariants:

  • Mutual Exclusion: The queue lock (q->lock) is acquired only during rapid pointer manipulation and counter increments, minimizing critical section duration.
  • Condition Signaling: When the queue is empty, worker threads execute pthread_cond_wait(&q->not_empty, &q->lock). Threads surrender their time slice to the operating system scheduler rather than spinning in CPU-wasting loops.
  • Atomic Termination Guarantee: A worker thread exiting cannot simply check q->count == 0, because sibling threads may be traversing subdirectories and about to enqueue more files. The system terminates cleanly if and only if: $$\text{Shutdown} \iff (\text{queue\_count} == 0) \land (\text{active\_workers} == 0)$$ When both conditions hold, q->shutdown = true is set, and pthread_cond_broadcast(&q->not_empty) awakens all threads to exit safely.

5. Deep Content Matching & I/O Optimization

The content search subsystem in c_engine/search.c implements several key performance heuristics:

  • Null-Byte Binary Detection: The first 1,024 bytes of every candidate file are inspected. If any null byte (\0) is discovered, the file is identified as a binary artifact (e.g., compiled object files, executables, images) and skipped, avoiding gigabytes of irrelevant regex processing.
  • Buffered File Scanning: Files are read using buffered I/O streams with line-by-line boundary tracking.
  • Context Snippet & Line Extraction: When a substring match is found, the exact line number and surrounding text snippet are extracted and escaped into JSON.
  • Independent Telemetry Locks: Each thread maintains an isolated WorkerTelemetry struct with its own mutex, preventing telemetry logging from becoming a lock contention point.

6. Empirical Benchmarks & Amdahl's Law

6.1 Theoretical Amdahl's Law Formulation

Amdahl's Law models the theoretical maximum speedup $S(n)$ achievable by adding parallel processors:

$$S(n) = \frac{1}{(1 - P) + \frac{P}{n}}$$

Where $P$ is the parallelizable proportion of execution (file content grep and directory scanning) and $(1 - P)$ is the strictly serial portion (initial thread spawning, CLI argument parsing, file queue locking). For AeroSearch, profiling indicates $P \approx 0.88$.

7. Technical Challenges & Resolutions

Challenge Root Cause Engineering Resolution
Missing DLLs on Host MinGW dynamically links libwinpthread-1.dll by default. Statically linked runtime libraries using -static to produce a 100% self-contained binary.
Windows Path Backslash Escaping JSON decoders crash when encountering raw backslashes (\). Built an in-place C sanitizer (escape_json) converting backslashes to forward slashes.
Browser Event Saturation Streaming every single scanned file over WebSockets froze browser rendering. Added a decoupled 60ms interval reporter thread in C to pulse aggregated telemetry.
